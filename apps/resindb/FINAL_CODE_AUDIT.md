# ResinDB Pro final code audit

## Audit scope

The audit covers project structure, React/Vite architecture, independent data assets, UI components, adapters, scientific workers, chart and export modules, tests, GitHub Actions, documentation, dependency integrity and release evidence.

## Findings and remediation

| ID | Finding | Risk | Remediation |
|---|---|---|---|
| AUD-01 | Complete catalog JSON lived below `src/data` and was statically imported. | Vite could embed the resin catalog into JavaScript and force data releases to rebuild UI code. | Moved authoritative documents to root `data/`; loader now uses runtime fetch; build proves sentinels are absent from JS. |
| AUD-02 | Data files had no repository-level version, metadata, schema and digest inventory. | Corrupted or mismatched assets could load without an auditable release boundary. | Added version, metadata, two JSON Schemas, manifest byte counts and SHA-256 validation. |
| AUD-03 | Runtime data failures could not be surfaced as a coherent catalog status. | Partial/fallback data could be mistaken for a complete dataset. | Added `RESIN_DATA_STATUS`, bounded fetches, integrity checks, deterministic recovery data and visible UI feedback. |
| AUD-04 | Package, README and feedback diagnostics remained at 3.0.0 while later documentation described newer work. | Version drift weakens traceability. | Aligned package, lockfile, feedback metadata, README, data version and validation contract to 3.2.0. |
| AUD-05 | Full-package ECharts imports and a catch-all vendor chunk inflated chart and entry bundles. | Large preload/bundle could reduce lazy-loading benefits and slow first interaction. | Added a modular ECharts registry and explicit React/UI/visualization/Markdown chunks. Current candidate metrics are 169,612-byte entry gzip and 887,575-byte ECharts raw, within unchanged 350,000/900,000-byte gates. |
| AUD-06 | Browser evidence covered only two dashboard states. | Details, empty state, analysis, network interaction and mobile layout could regress unnoticed. | Expanded Chromium smoke to seven functional screenshots and explicit interaction checks. |
| AUD-07 | README diagrams were strong but did not cover the requested domain-specific scientific analyses. | Project capabilities were difficult to assess from the repository landing page. | Expanded the deterministic visual system from 14 to 22 diagrams, including structure-property, molecular, rheological, thermal, mechanical, electrical, multiscale and AI discovery workflows. |
| AUD-08 | Latest durable report explicitly relied on composite evidence rather than a fresh final-tree Actions run. | A cleanup or documentation change could escape validation. | Final CI is required to validate the exact candidate SHA and produce machine-readable status plus artifacts. |
| AUD-09 | One-time workflows and diagnostic receipts from interrupted remediation remained possible. | Repository hygiene and CI trust could degrade. | Final tree validator rejects triggers, patch payloads, temporary workflows and diagnostic residue; all one-time export files are removed before release. |
| AUD-10 | No exact-candidate PDF/HTML validation package was a permanent release gate. | Visual and test evidence was fragmented. | CI now generates Markdown, HTML, PDF, UI PNGs and a receipt in one evidence artifact. |
| AUD-11 | `UniversalStorageBridge` still statically imported the former `src/data/*.json` catalogs after the main loader was externalized. | The catalog could be re-embedded through an adapter path and TypeScript would fail after the files moved. | Removed the static imports and routed bridge seed data through the single runtime catalog loader. |
| AUD-12 | A Worker dependency reached the top-level-await data loader through shared UI constants. | Vite could not emit the Worker in IIFE format and the production build failed. | Split pure UI defaults into `src/config/uiDefaults.ts`, keeping Worker graphs synchronous and independent from runtime data fetch. |
| AUD-13 | Browser automation could fail without producing a complete scene inventory or actionable navigation diagnostics. | A nominal smoke result could omit details, network interaction or responsive states. | UI smoke now verifies seven named scenes, console errors, preferences, click feedback and screenshot existence; final acceptance is delegated to the exact-tree GitHub runner because this sandbox blocks loopback Chromium navigation. |
| AUD-14 | Placeholder detection treated numeric zero and all nonnumeric text as missing. | Valid zero measurements, categorical ratings and completeness scores were silently discarded. | Missingness now uses explicit markers only; finite zero and legitimate text are preserved, with property-specific physical limits applied separately. |
| AUD-15 | Short category aliases were matched as raw substrings. | `TPE` could be classified as `PE`, and `PPR` could be classified as generic `PP`. | Short ASCII aliases now require token boundaries; longer aliases remain longest-first semantic matches. |
| AUD-16 | Local and remote adapters accepted non-finite or structurally invalid values. | NaN values or malformed API JSON could enter state and fail later in charts or reports. | Storage conversion keeps finite numbers only; remote Product and Product-array responses are validated at the HTTP boundary. |
| AUD-17 | AI configuration and output handling trusted browser storage, image payloads and parsed JSON shapes. | Storage denial, oversized images/responses or malformed AI JSON could crash the settings or analysis flow. | Added storage error handling, session-only keys, HTTPS/credential checks, MIME/Base64/size limits, response-size limits and runtime response normalization. |
| AUD-18 | Coverage reported only files imported by tests, producing an inflated 71% figure. | The repository could appear well covered while most UI and hooks had no instrumentation. | Coverage now instruments all 191 production TypeScript files and enforces non-regression floors against the honest whole-source baseline. |
| AUD-19 | Test counts and acceptance state were hard-coded in CI/report generators. | Adding or losing tests could leave a falsely consistent report. | Vitest emits machine-readable results; a validation receipt derives counts and PASS only from exact-tree tests, coverage, browser evidence, audits, build budgets and single-main proof. |
| AUD-20 | The security diagram claimed an application CSP that was not present in the browser bundle. | Documentation overstated a deployment control. | The diagram and policy now state that CSP is a hosting/gateway responsibility and must be deployed and tested externally. |
| AUD-21 | Whole-source coverage generated a full HTML site for 191 files inside the blocking CI gate. | Report generation took several minutes and could make a healthy test suite appear hung. | The gate now emits terminal, full JSON and summary JSON coverage only; the same 191-file evidence completes in about 16 seconds. |
| AUD-22 | Long acceptance states overflowed the PDF metric card. | A valid report could be visually clipped even when its underlying receipt was correct. | Added measured single-line font fitting and regression tests for PASS, FAIL and EVIDENCE_INCOMPLETE layouts. |

## Acceptance

This audit is closed only by a successful exact-tree GitHub Actions run with the sole remote branch `main`. The generated final report records the commit SHA, gate results, data boundary, coverage, build metrics and UI evidence.
