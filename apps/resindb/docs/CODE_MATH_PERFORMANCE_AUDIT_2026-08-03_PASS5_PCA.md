# ResinDB Pro 数理程式与性能审计：第五轮 PCA（2026-08-03）

## 1. 本轮范围

本轮只审查 `src/lib/math/pca.ts` 及其在科研散点图中的主成分投影用途，不混入其他 Legacy 组件拆分。目标是同时修复数值正确性、秩亏稳定性和高频内存分配，并保持现有 API：

```ts
PCA.getComponents(data, numComponents)
// => { projected, loadingVectors }
```

模型仍为**均值中心化、未标准化的 NIPALS PCA**。本轮不引入缺失值插补、不把 PCA 解释为因果模型，也不静默改变变量单位。

## 2. 已确认的原实现问题

### A1. 固定使用第一列初始化

原算法每个主成分都用残差矩阵第一列初始化 score 向量。如果第一列为常量，而其他列存在变化，则 `tᵀt = 0`，算法会提前停止并输出零 loading，尽管数据实际存在可提取主成分。

### A2. 秩亏数据产生重复伪主成分

对严格共线数据，第一主成分提取后只剩浮点舍入残差。原实现仍继续迭代，因此可能把数值噪声再次输出为方向几乎相同的“第二主成分”。这违反主成分正交性，也会误导显示层。

### A3. 非矩形行未被拒绝

原过滤只检查每个已有元素是否有限，没有要求每行列数一致。短行中的缺失位置会在均值累加时变成 `undefined`，继而污染整个矩阵。

### A4. 迭代期临时分配过多

原实现使用嵌套数组复制中心矩阵、残差矩阵，并在每次迭代创建 `oldT = [...t]`。大数据投影会产生不必要的短生命周期数组和垃圾回收压力。

## 3. 实施修复

- 每个成分从**当前残差能量最大的列**初始化，不再依赖第一列是否有方差；
- 用相对于总中心化能量的阈值判断数值秩，残差能量不足时停止提取；
- 对 loading 执行修正 Gram–Schmidt 正交化；
- 按 loading 中绝对值最大的元素统一符号，确保重复运行方向确定；
- 只接受有限且与第一行等宽的矩形行；
- 使用扁平 `Float64Array` 保存残差矩阵；
- 复用 score、previous score 和 loading 工作区；
- 保留请求范围内的零 score 列，使秩亏结果在显示层仍保持有限、稳定的投影形状；
- 不修改调用方输入。

## 4. 数值核验

新增 `tests/unit/pca.test.ts`，锁定以下合同：

1. 第一列常量、第二列变化时仍能提取正确主成分；
2. 严格共线矩阵只返回一个有效 loading，后续 score 为零；
3. 全秩夹具返回单位长度且互相正交的 loading；
4. score 均值为零；
5. 非有限和非矩形行被排除；
6. 单观测和全无效输入返回有限、显式结果；
7. 输入数组保持不变。

另以 80 × 7 的确定性随机矩阵与 NumPy SVD 做本地交叉核验：前五个 loading 与 SVD 主方向的绝对内积在打印精度下为 1；对应 score 能量最大相对差约 `2.74 × 10⁻¹⁰`；五成分重构残差范数与 SVD 尾部奇异值范数一致至约 `3 × 10⁻¹⁵` 的绝对差。

## 5. 性能核验

本地环境：Node.js 22.16.0；确定性 8,000 × 24 数据；提取 2 个主成分；预热后各运行 7 次并取中位数。

| 实现 | 中位时间 |
|---|---:|
| 原嵌套数组实现 | 45.52 ms |
| 新扁平工作区实现 | 15.34 ms |

当前夹具约为 `2.97×` 加速。该数值只描述当前设备与夹具，不作为跨浏览器、跨设备固定倍数承诺。性能收益主要来自扁平连续存储、工作区复用和移除迭代期数组复制。

## 6. 保留边界

- PCA 仍基于协方差方向，而非自动 Z-score 标准化；量纲差异需要调用方明确处理；
- 行过滤仍采用完整有限案例，不执行统计插补；
- 特征选择与界面中缺失值策略属于上游显示链问题，本轮不在缺少统一科学合同的情况下擅自改变；
- 特征值接近简并时，任何 PCA 实现都可能在等价子空间内选择不同但同样正确的基；本实现保证同一输入下的确定性方向，不把简并子空间解释为唯一物理机制；
- 最终接受状态以 PR 的 TypeScript、完整测试、覆盖率、构建、Chromium 和依赖审计结果为准。
