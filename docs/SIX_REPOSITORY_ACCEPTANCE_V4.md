## 六小时真实测试协议

六仓分别绑定最终 SHA。每仓累计不少于 21,600 秒有效测试时间；不得将六仓各一小时相加冒充每仓六小时，不将并行任务的重叠时间重复相加。使用单调时钟记录每个成功测试进程的开始、结束、退出码、命令、日志 SHA-256、源提交和树身份。安装、排队、sleep、等待和失败进程不得计入有效时间。任何测试失败使该次认证失败；修复后的新 SHA 必须重新开始，旧证据可以归档但不能继承为新 SHA 的验收。

GitHub 托管 runner 的单任务上限为六小时，安装和上传同样占用任务时长。因此采用每仓顺序的两个三小时有效测试阶段，六仓横向并行；阶段间断开必须标为 segmented-regression，不冒充同一个服务进程的连续泄漏/存活测试。真正连续六小时服务 soak 需要有足够运行上限的授权 runner，另行记录其证据。每阶段留出安装、单次测试收尾和工件上传余量，任一阶段缺失或超时即 SOAK_INCOMPLETE。最终验收检查两阶段仓库/SHA/树一致、阶段顺序、不重叠、有效秒数达标、日志完整和所有门禁通过。
