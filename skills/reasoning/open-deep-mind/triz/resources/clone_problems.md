# Clone Problems / 克隆问题迁移

Clone-problem application generalizes the structure of one solved problem and transfers the **solution approach** to another problem with a structurally similar contradiction/function. In current MATRIZ routing it can supplement physical-contradiction solving.

## Purpose

Use when:

- a physical contradiction is clear;
- a structurally similar contradiction has a known solution pattern;
- direct separation/principle search is weak;
- the source and target share a real mechanism/constraint structure.

## Procedure

1. State target physical contradiction precisely.
2. Abstract the contradiction from domain nouns:

```text
Element X must be A under condition C1
and not-A under condition C2
```

3. Search known problems/cases with the same separation variable or mechanism structure.
4. Extract the **resolution schema**, not the visible object.
5. Map source resources/conditions to target resources/conditions.
6. Identify mismatches.
7. Translate the schema into a target-domain physical embodiment.
8. Validate the mechanism independently.

## Anti-pattern

A visual analogy is not a clone problem.

Bad:

```text
“Nature uses honeycombs, so a honeycomb geometry solves our thermal contradiction.”
```

Better:

```text
The source system resolves stiffness-vs-mass by spatially separating load-bearing material
and void while maintaining section depth. Does the target have the same load paths,
manufacturing constraints, instability modes, and thermal requirements?
```
