# Feature Transfer / 特征迁移

Feature transfer improves a **base system** by identifying a competing/alternative system that performs the same or similar main function with a complementary advantage, then transferring the useful feature/mechanism while resolving incompatibilities.

## Definitions

- **Base system:** the system selected for improvement.
- **Competing system:** a system performing the same or similar main function; it may come from another industry, scale, environment, or principle of operation.
- **Alternative system:** a competing system with a complementary advantage/disadvantage pattern relative to the base.
- **Feature-transfer problem:** a key problem created when the desired feature cannot be copied directly without losing the base system's advantages.

## Procedure

1. Formulate the base system's **main function** correctly.
2. Identify its key disadvantage(s) and desired feature(s).
3. Search for competing systems using the main function, not category labels.
4. Compare base and candidates on MPVs, useful functions, disadvantages, cost, resources, mechanism, and operating envelope.
5. Select an alternative system whose advantage directly addresses the base disadvantage.
6. Identify the physical/structural feature or mechanism responsible for that advantage.
7. Ask whether the feature can be transferred directly.
8. If not, formulate the incompatibility as one or more **feature-transfer problems**.
9. Solve those problems with contradictions, separation, Su-Field/SIS, FOS/effects, trimming, or ARIZ.
10. Build and validate the hybrid/new concept.

## Simplified advantage CECA

Unlike normal CECA, a feature-transfer analysis may trace **why an advantage exists** in the alternative system:

```text
Alternative advantage
← mechanism / feature
← enabling structure/material/field/resource
```

This is not a license to infer causality from superficial resemblance; verify the mechanism.

## Transfer hierarchy

Prefer transferring:

1. causal mechanism;
2. structural relation;
3. field/material interaction;
4. control principle;
5. resource-use pattern;
6. geometric/architectural feature;

rather than merely copying surface appearance.

## Cross-domain search

Competing systems can be far outside the original industry if the generalized main function matches. Record both structural matches and mismatches:

## Anti-patterns

- copying a fashionable technology because it is from another industry;
- searching by product name rather than function;
- transferring an attribute without the mechanism that creates it;
- ignoring operating-condition differences;
- claiming analogy as proof;
- creating a hybrid that simply accumulates both systems' disadvantages.
