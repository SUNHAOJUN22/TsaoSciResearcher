# Multi-Screen / System Operator / 多屏幕系统算子

Use the multi-screen view to escape a problem frame locked to one component and one moment. The common 9-screen form crosses **system level** with **time**.

## 3×3 core

|  | Past | Present | Future |
|---|---|---|---|
| **Supersystem** | prior environment/infrastructure | current supersystem | future supersystem / integration |
| **System** | predecessor system | analyzed system | next-generation system |
| **Subsystem** | prior component/material mechanism | current components/mechanism | future microstructure/components/mechanism |

The “screens” are prompts, not deterministic future predictions.

## Procedure

1. Define the current analyzed system and main function.
2. Move **up**: what supersystem contains/enables/constrains it?
3. Move **down**: which subsystems/material structures/fields actually create behavior?
4. Move **left**: what predecessor architecture/mechanism existed, and why did it change?
5. Move **right**: what transitions are suggested by unresolved contradictions, resources, S-curve/TESE, and competing systems?
6. Look for resources/functions that can be transferred across screens.
7. Reformulate the problem at at least one different screen.

## Extended questions

### Supersystem

- can the environment perform a function currently assigned to the system?
- can multiple systems integrate and share components/resources?
- which infrastructure or neighboring system creates the limiting condition?

### System

- which main parameter of value is binding?
- which component/function dominates payment factors?
- which contradiction controls the current architecture?

### Subsystem / microlevel

- can a material/interface/phase/field perform the function directly?
- is the apparent system-level contradiction resolved by heterogeneity or microstructure?
- can segmentation/dynamization reduce component burden?

### Time

- predecessor: which historical constraint produced the current design?
- present: which constraints are still real?
- future: which constraint might disappear or become dominant?

## Integration with ARIZ and TESE

Use the multi-screen view to:

- identify additional substance-field resources;
- choose a better operating zone/system boundary;
- locate supersystem solutions;
- generate micro-level physical-contradiction routes;
- create TESE roadmap hypotheses;
- discover trimming/feature-transfer opportunities.
